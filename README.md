# Collector

Collector 是一款跨平台（macOS + Windows）的本地素材管理器，用于集中管理并一站式查看/运行三类本地素材：

- **视频**：MKV 影片，按「电影 / 动漫 / 剧集」分类。
- **漫画**：zip 图片包。
- **游戏**：绿色版（免安装）游戏。

它提供两条能力线：

1. **素材标准化**：影视海报自动抓取（TMDB）、字幕批量校准（.ass 中英合并、中英标点各自规范、特殊字符/OCR 纠错、统一样式与分类，附质检报告）、漫画自动归档（按卷打包为 zip）、系统数据整理。
2. **一站式查看**：主页概览、内置视频播放器、漫画阅读器、游戏启动器。

技术栈：Tauri 2.x（Rust 后端 + WebView 前端，vanilla-ts）、SQLite 索引、ffmpeg 转 HLS + hls.js/MSE 播放、玻璃拟态 UI。

## 功能概览

- **主页**：科技感深色渐变背景，展示各类目统计（影视按电影/动漫/剧集细分、漫画、游戏）与当前版本号；三个统计面板可点击直达对应菜单，悬停时轻微放大并发光。
- 三类素材统一扫描、索引（SQLite）与浏览；文件夹视图中文件夹显示为无边框的大号文件夹图标（悬停整格高亮并发光），带封面的具体条目用长方形，同页文件夹与文件分区展示、中间以分割线隔开，分区标题显示「共 xx 项」。
- 树形视图：单击箭头或双击标题展开/折叠，展开、选中时保持滚动位置；滚动条为细的半透明样式，与深色主题融合。
- 就地新增：在当前所在文件夹下新增素材（视频/漫画/游戏）。
- 编辑面板（右侧滑出）：标题、路径、封面、简介分区展示；路径按当前系统显示分隔符（Windows `\`、macOS `/`，仅显示，库内不变）；影视封面可「选择图片」或「自动抓取」（按标题从 TMDB 获取，保存后生效）；漫画只编辑标题与简介。
- 视频：内置播放器（ffmpeg 转 HLS + hls.js/MSE），首段（~2s）就绪即起播、开播时间与总时长解耦；打开时分阶段显示加载进度（检查缓存 → 读取信息 → 转码 → 首段 → 播放列表 → 缓冲），进度条上显示已缓存范围，失败时显示原因并可重试；缓存复用秒开、按返回不打断继续在后台完成缓存、下次打开续转；AC-3 音轨在 Windows 上自动转 AAC（Chromium 无 AC-3 解码器）；**多音轨视频可在播放条的「音轨」按钮里切换音轨**（视频与每条音轨各自成流，切换时只换音频、画面不停，约半秒后听到新音轨；每部视频记住上次选的音轨）；支持外挂 `.ass` 字幕、封面、简介侧载；全屏铺满整个屏幕（原生窗口全屏），工具栏随鼠标移动显隐、字幕正常显示。
- 漫画：zip 包内置阅读器，自动提取首图作为卷封面；浏览时目录与作品都以文件夹显示、合并按名称排序（英文在前，中文按拼音），只有进入作品后的「卷」列表显示封面；从卷列表返回回到作品所在目录；首屏按页名秒开、页尺寸后台补正；翻页有卷动动画。
- 游戏：按平台启动绿色版游戏；当前平台无对应可执行文件时仍显示但标注「本平台不可用」。
- 独立的**工具箱**：字幕批量校准、漫画自动归档、系统数据整理（数据库重置、无效封面清理），长任务带进度条，切换菜单不中断。
- **设置**：「路径设置」配置各素材根目录，并可对电影 / 动漫 / 剧集 / 漫画 / 游戏各自导出为 zip、从 zip 无损还原（带类型校验与进度条）；「服务管理」填写 TMDB API Key，旁边的「注册 TMDB」在浏览器中打开 TMDB 注册页；「视频缓存」查看用量与清空。

## 开发依赖

- **Node.js**（前端构建 / Tauri CLI）
- **Rust**（后端）
- **ffmpeg**（视频转码与时长/音轨探测，只需 `ffmpeg` 一个二进制，不再需要 ffprobe）
  - 已内置：macOS `.app` 与 Windows 安装包均随包自带 ffmpeg，终端用户**无需自行安装**。
  - 开发/打包：构建前运行 `npm run fetch:ffmpeg` 自动下载对应平台二进制到 `src-tauri/bin/`（不入 git）；`npm run tauri:build` 会自动前置执行。Windows 使用 BtbN 的 LGPL 静态构建（约 80 MB）。
- **Windows ARM64 额外需要**：Visual Studio Build Tools（C++ 工作负载，含 Clang 组件——`ring` crate 在 aarch64 上需要 clang 编译）。

## 快速开始

```bash
# 安装前端依赖
npm install

# 开发模式（热重载）
npm run tauri:dev

# 构建生产包（会自动前置 npm run fetch:ffmpeg 下载 ffmpeg）
npm run tauri:build
```

### Windows 本机构建与部署

```bash
# 加载 MSVC 环境 → 构建 → 按白名单清理构建产物（约 2 GB）→ 启动
npm run deploy:win

# 只清理，不构建；预览要删什么：在 scripts/deploy.ps1 后加 -DryRun
npm run clean:win
```

程序直接从 `src-tauri/target/release/collector.exe` 运行（不打安装包），由 `explorer.exe` 启动，确保数据写入真实的 `%APPDATA%\com.zhoumo.collector`（若从 Claude 桌面版等 MSIX 打包应用里直接启动，Windows 会把 AppData 写入重定向到该应用的沙盒目录）。清理只删除 `scripts/deploy.ps1` 中固定列出的路径（`dist`、cargo 中间产物、`target/release/seed` 副本等），保留 `collector.exe`、`ffmpeg.exe` 与 `src-tauri/bin`。代价是下次构建需完整编译（约 4–6 分钟）；传 `-KeepCache` 可保留 cargo 缓存。

## 素材根目录约定

在应用「设置」中分别配置三个根目录，扫描后按以下约定识别素材。

### 视频

```
<视频根>/<分类>/.../<剧名>/*.mkv
```

- **分类**取第一级目录名（电影 / 动漫 / 剧集），支持多级子目录递归。
- 侧载文件（放在与 `.mkv` 同目录）：
  - 同名 `.ass`：外挂字幕
  - `poster.jpg` 或同名 `.jpg`：封面
  - `info.txt`：简介

### 漫画

```
<漫画根>/<分类>/.../<漫画名>.zip
```

- zip 内含 jpg / png 图片。
- 封面自动取 zip 内的首张图片。
- 同名 `.txt`：简介。

### 游戏

```
<游戏根>/<游戏名>/
```

每个游戏目录内放一个 `game.json`。封面为同目录的 `cover.jpg`。

`game.json` 字段：

| 字段          | 类型            | 必填 | 说明                                                        |
| ------------- | --------------- | ---- | ----------------------------------------------------------- |
| `name`        | string          | 是   | 显示名                                                      |
| `description` | string          | 否   | 简介；缺失时读取同目录 `info.txt`                           |
| `exec_win`    | string          | 否   | Windows 启动程序相对路径                                    |
| `exec_mac`    | string          | 否   | macOS 启动程序相对路径（如 `Xxx.app`）                      |
| `fullscreen`  | bool            | 否   | 是否全屏启动                                                |

> 当前平台无对应 `exec` 的游戏仍会在列表中显示，但标注「本平台不可用」。

## 标准化工具台

独立菜单，提供两类素材标准化工具。

### 字幕批量校准

选择输入目录（可配置、自动记住；默认 `docs/subtitles`），递归校准目录下所有 `.ass` 字幕，**输出固定写入应用字幕库**（`<应用数据目录>/subtitles/<分类>/<相对目录>/<标题>.ass`，与播放器所用字幕同一份文件），处理完附质检报告。输出目录不存在时自动创建，旁边的「打开」按钮在资源管理器 / Finder 中直接打开（Windows 为 `%APPDATA%\com.zhoumo.collector\subtitles`，macOS 为 `~/Library/Application Support/com.zhoumo.collector/subtitles`）。

校准遵循一条核心原则：**能确定的自动修改，有语义判断风险的只在结果列表提示、不擅自臆改**。

#### 自动执行的规则（会改写字幕）

1. **编码兼容**：自动识别并解码 UTF-8（含 BOM）、UTF-16（带 BOM）、GBK；无法识别的文件跳过并在报告中提示，不中断整批。
2. **跳过空文本行**：仅含特效标签（`{\pos..}`、`{\shad1}` 等）、`\N`、空白而无实际文字的 `Dialogue` 行直接剔除，不输出、不参与检测。
3. **中英合并**：开始与结束时间**完全相同**的多条 `Dialogue`（一中一英）合并为一条「中文 + 英文」双语字幕，用标准分隔符 `\N{\fnArial\fs30}` 连接——相邻的直接合并；中文块、英文块分开存放（同轴但不相邻）的，在整个文件里该时间轴恰好一中一英两条时配对合并，落在先出现的位置。同一条内已有的 `\N{...}` 分隔统一为标准分隔符；「中文`\N`英文」这种不带标签的裸换行同样换成标准分隔符（「中文`\N`中文」等同语言换行保持原样）。
   - **删除 `{\r}`**：样式复位标签 `{\r}` 在统一样式后已无意义，输出中全部删除。
   - **音乐符统一为 `♪`**：旧的音乐符 `∮` 一对一替换为 `♪`（中英两段都换）。输入可以是 UTF-8 / UTF-16，输出一律 UTF-8，`♪` 不会因编码变成乱码。
4. **中文标点体系**（仅作用于中文段）：半角标点转全角——`, → ，`、`! → ！`、`? → ？`、`: → ：`、`... → …`、`. → 。`；成对英文引号 `"` 按奇偶配对转为 `「` `」`。
5. **英文标点体系**（仅作用于英文段）：标点前多余空格移除、逗号后补空格、多空格并一；行尾若以字母/数字结尾补英文句号。中英两段严格分开处理，互不串扰。
6. **特殊字符 / OCR 纠错**（数据表驱动，可扩展）：`'' → "`、`-- → …`、连续 2+ 个点 → `…`、多空格 → 单空格；常见 OCR 误识别修正（如独立的 `l`/`i` → `I`、`lt' → It'`、`lsn' → Isn'`）。
7. **对话破折号规整**：把已标注的对话破折号统一为「`- `」（破折号后恰一个空格），中英各自对齐；**不臆测**某句是否为对话。
8. **已标注标记规整**：中文段圆括号 `()` 全角化为 `（）`并去内侧多余空格；方括号 `[]`（外语）、井号 `#`（歌曲）保留并去内侧多余空格；紧贴在 `《` 前面的空格一律删除（`是 《奇异恩典》啊` → `是《奇异恩典》啊`）。整行被括号包裹的注释行例外，见下一条。
9. **统一样式与分类**：输出统一的 ASS 样式头，共四种样式，按下列顺序命中即止（判断只看中文段的可见文字，忽略 `{...}` 标签）：
   - **`Bilingual`**：有英文译文的中英双语行（两行）。
   - **`Title`**：整行就是一对 `《…》`。`《XXX》后面还有字`、`前面有字《XXX》` 都不算。书名号内的冒号统一为中文冒号 `：`，并删除全部空格。
   - **`Note`**：整行被一对 `(…)` 或 `[…]` 包裹。中文括号统一改成英文括号（`（）→()`，`【】`、`［］→[]`）。
   - **`Unilingual`**：其余单行字幕，样式参数与 `Note` 相同。

   「完整包裹」指开头的括号与结尾的括号是同一对：`(电话(626) 584)` 算（嵌套不影响），`(枪声)(枪声)` 不算（多段拼接），`[外语] 早上好` 不算。`Bilingual` 之外的三种样式只包含单行，方便以后按类型整体调整样式。

#### 仅提示、不自动修改（列在结果列表，人工核对）

- **疑似未合并中英**：相邻两条时间轴很接近（开始、结束差都 ≤ 0.5 秒）且一中一英，疑似本应合并却没对齐；右侧图标点击复制标准中英分隔符 `\N{\fnArial\fs30}` 到剪贴板。
- **时间轴交叉**：按时间排序后，某条与其前后各 3 条存在区间重叠（时间轴**完全相同**的中英对属正常，不报）。
- **同时间轴多于 2 条**：同一时间轴出现 3 条以上，只取中/英各一条，其余需人工确认。
- **残留可疑标点**：所有标点类问题统一归这一类，一行只报一条，不再按具体标点细分。目前包含：`,.`；连续两个空格；`.,`（仅在点号前不是字母时才提示，英文缩写如 `D.C.,`、`Jan.,` 属正常，不报）。
- **疑似漏译**：双语字幕中只有中文、且未被 `（）` `《》` `[]` `#` 整行包裹的行（疑似漏加注释标记）；行首带 `[外语]` 等标签的行，以及 `- [外语] … - [外语] …` 形式的多人对话不报。该类提示右侧有「标记为外语」图标，点击复制 `[外语] `（含末尾空格）到剪贴板，供人工修改。只有英文的行报「疑似漏译(仅英文)」。
- **非标准音乐符**：用了 `♫♬♩` 等乐符的行，建议统一改为规范音乐符 `♪`；右侧图标点击复制 `♪` 到剪贴板。
- **异常字体**：校准后的正文里除标准中英分隔符自带的 `{\fnArial\fs30}` 外，还残留 `{\fn…` 字体覆盖标签（如 `{\fn微软雅黑}`、`{\fnKaiTi\fs20}`）。
- **样式存疑**：归类时拿不准、留给人工判断的行，不自动改。
  - **样式存疑(双语)**：双语行的中文段被 `《》` 或括号完整包裹（如 `《小红帽》` + `Snow White?`），按 `Bilingual` 归类；若它其实是标题或注释，删掉英文即可归入 `Title` / `Note`。
  - **样式存疑(多段)**：单行由多段包裹拼成（如 `(枪声)(枪声)`），按 `Unilingual` 归类。
  - **样式存疑(未闭合)**：单行以圆括号开头却没有完整包裹（如 `（两天没换的衬衫`、`（贝克街） 221号B`），或开头的方括号 / 书名号整行没有闭合，按 `Unilingual` 归类。
- **读取失败**：编码无法识别的文件。

结果列表按文件分组、可折叠，每条提示带类型色标、字幕起止时间与文本摘要；双击提示可打开编辑器，定位到原字幕对应行修改时间轴/正文，保存后自动重校该文件、关闭编辑器，并只刷新该文件的提示列表（保持展开，已修好的记录消失）。

> 语义判断类内容（哪句是对话、哪句是道具翻译 / 外语 / 歌词）不做自动识别，避免误伤正常字幕——引擎只规整你已经标注好的，并把可疑之处挑出来供人工处理。

### 漫画自动归档

遍历设置中配置的漫画根目录，把每个「直接包含图片」的目录识别为一卷：

- 同一漫画（父目录）下的卷按目录名自然序编号，打包为 `Vol_01.zip`、`Vol_02.zip`……（位数随卷数自动调整），写在漫画目录下；
- 卷内图片按自然序排列；系统冗余文件（`.DS_Store`、`Thumbs.db` 等）自动忽略；
- 幂等：目标 zip 已存在则跳过；单卷失败只记录该卷，不中断整批。完成后自动重扫漫画库。

### 系统数据整理

- **数据库重置**：三张表按分类 → 目录 → 标题重新排序，ID 从 1 重新编号（单事务，失败回滚）；完成后提示「重置完成：影视 xxx 条、漫画 xxx 条、游戏 xxx 条。」
- **无效封面清理**：删除库中未引用的孤立封面图片；库中引用但文件缺失的仅提示、不改库；完成后提示「删除孤立图片 xxx 个；发现缺失文件 xxx 个。」

## 分类数据包导入/导出

「设置 → 路径设置」中影视（电影 / 动漫 / 剧集）、漫画与游戏各分类的目录按钮后有「导入」「导出」，执行时在该行下方显示进度条。

- **导出**：生成 zip，包含 `manifest.json`（类型校验：格式、版本、分类、导出时间、文件清单）、`data.json`（该分类全部条目）与 `files/`（封面、字幕，按应用数据目录内的相对路径存放）。
- **导入**：先校验 `manifest.json`——不是本应用的包、版本不支持、类型不符（如把电影包导入到动漫）或文件缺失，一律拒绝且不做任何改动；校验通过后清空该分类，整表按分类顺序重排、ID 从 1 重新编号，再按包内容无损还原，封面/字幕放回应用数据目录（同名但内容不同的封面自动改名）。数据库在单事务内完成，失败回滚。

## 更新日志

### v0.1.10

- **视频播放：多音轨切换**
  - **音轨按钮**：多音轨视频的播放条上新增「音轨」按钮，点开列出全部音轨（语言、标题、原始编码与声道），单音轨视频不显示。
  - **切换不卡画面**：视频与每条音轨各自成流（一路纯视频 + 每条音轨一路），切换时只换音频、视频缓冲不动，约半秒后听到新音轨；转码进行中同样可以切。

  - **编码统一**：多音轨视频里非 AAC 的音轨一律转 AAC 192k 立体声（各路编码必须一致才能切换），AAC 音轨原样保留；视频始终原样复制。
  - **缓存**：多音轨视频的旧缓存失效、下次打开重新转码一次，半截缓存不续转（从头重转，起播仍只等首段）；单音轨视频不受影响，旧缓存照常使用。

### v0.1.6

- **视频播放：HLS 边转边播 + 断点续转**（重构自 v0.1.5 的一次性 mp4 转封装）
  - 转码流水线由 ffmpeg 输出 HLS（`.m3u8` + `.ts` 段）、前端用 hls.js 走 MSE 播放；**首段（~2s）就绪即起播**——开播时间与视频总时长解耦
  - 用户按返回时 ffmpeg **优雅退出**（写 `q\n`、写完当前段、追加 playlist）；已缓存的段保留在磁盘上、Settings 缓存利用率实时反映
  - 下次打开同视频走**续转分支**（`-ss` 输入 seek + `-hls_start_number` 段号续写 + `-hls_flags append_list` playlist 追加）——从上次退出的段号开始继续追加，直到写入 `#EXT-X-ENDLIST` 才算完整
  - 完整缓存 = 秒开复用（`playlist_is_complete` 检查 ENDLIST 标记）
- **AC-3 音频**：在 Windows 上被 Chromium 静音的问题——ffmpeg 单独转 AAC（`-c:a aac -aac_coder fast -b:a 192k -ac 2`），视频保持 `-c:v copy` 零重编码
- **自定义 `hls://` URI 协议**：绕开 Tauri asset 协议对 fetch 的 404 限制与 WebView2 对 `http://localhost:PORT` 的拦截；handler 服务 `<app_data>/video_cache/collector_*.{m3u8,ts}`，含 ffmpeg 追加段时短暂 file-not-found 的重试兜底（`.tmp` fallback + 20-100ms 递增重试）
- **缓存管理**：LRU 单元从"单个 mp4 文件"变为"按 hash 前缀分组"，playlist + 全部段一起淘汰；"清空缓存"识别并清理 v1-v5 (`.mp4`)、v6 (`.m3u8.part`)、v7 (`.m3u8`/`.ts`/`.ts.tmp`) 所有历史格式
