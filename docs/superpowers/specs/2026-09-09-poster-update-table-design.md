# 影视海报生成：更新海报 + 未命中表格（带优化建议）

## 目标

工具箱「影视海报生成」升级：
1. 按钮文案「抓取缺失海报」→「更新海报」。
2. 执行后在按钮下方展示一张美观表格，列出本次**未命中**（cover_path 仍为空）的视频。
3. 表格字段：序号、类型（电影/动画/剧集）、目录、名称、优化建议。
4. 优化建议基于失败规律，尽量给出「改成 XXX」的具体建议名（年份校验后才给名）。
5. 未命中视频**不自动改库**，由用户手动修改。

## 决策汇总

| 项 | 决策 |
|----|------|
| 按钮文案 | 更新海报 |
| 建议生成 | 后端对每个未命中条目额外联 TMDB 探测候选名 |
| 建议可信度 | 候选命中且 TMDB 年份与文件名年份同年(±1)才给「改名为 XXX」；否则只提示「请手动查证」 |
| 是否自动改库 | 否，只展示建议，用户手动改 |
| 表格排序 | 类型(电影>动画>剧集) → 类型内按目录 → 目录内按名称 |
| 目录显示 | 去掉首级分类，从下一级起（如 科幻/异形） |
| 单行显示 | table-layout:fixed + 固定列宽 + 超长省略(…)+ 悬停 title 看全文 |

## 数据流

```
点「更新海报」（工具箱）
  → invoke fetch_posters（沿用现有：后台线程，poster-progress 事件推进度）
     对每个空封面视频尝试抓取（现有规则：完整名→动漫fallback→副标题降级→季海报）
     成功 → 回填 cover_path；失败 → 记入 FailedItem（不改库）
     对每个 FailedItem 额外生成优化建议（见下）
  → 返回 FetchReport { ok, failed: [FailedItem{...}] }
前端：进度「成功 N，未命中 M」+ 表格（未命中项，前端排序 + 单行渲染）
```

## 后端改动

### FailedItem 扩展（src-tauri/src/poster/mod.rs）
现为 `{ title, reason }`，扩展为：
```rust
pub struct FailedItem {
    pub category: String,      // 电影/动漫/剧集（原始分类）
    pub category_path: String, // 完整目录，前端去首级显示
    pub title: String,         // 名称（文件名/条目 title）
    pub reason: String,        // 失败原因（搜索无结果/无海报等）
    pub suggestion: String,    // 优化建议文案
}
```
`fetch_posters` 记录失败时填入 category/category_path（当前只传了 title，需把 item 的这两个字段一并带上）。

### 优化建议生成（新函数，在 fetch_cover 失败分支或 mod 编排里）
对未命中条目，用与「改名分析」一致的策略联 TMDB 探测候选：
1. 候选名集合：原名去副标题主名(alt_name)、去末尾数字、目录末段(系列名)。
2. 对每个候选按 kind（含动漫 movie/tv 双试）搜索，取有 poster 的结果。
3. **年份校验**：候选命中结果的年份与该条目年份同年(±1) → 建议名可信 → suggestion = "译名/名称与 TMDB 不符，建议改名为「<TMDB中文标题>」"。
4. 年份对不上或无候选 → suggestion 按失败类型给通用提示：
   - 剧集季无独立海报 → "该季 TMDB 无独立海报，将回退整剧海报（可接受）"
   - 其它 → "未找到可靠候选，请手动查证官方译名，或用编辑封面手动上传"
5. 建议探测每条最多几次请求 + 限速，串行于抓取之后（避免拖慢主抓取）。

> 复用已验证的探测逻辑（见 scripts/poster_regression.py 的 parse/search），保证与实际抓取规则一致。

### 结果区改为表格
- 进度/汇总：「完成：成功 N，未命中 M」。
- 表格（glass 卡片内，最大高度 360px 可滚动，表头吸顶）：
  - 列：# / 类型 / 目录 / 名称 / 优化建议。

  - 单行：table-layout:fixed + 列宽 + 省略号 + 悬停 title。
- 无未命中项时：显示「全部命中，无需处理」，不显示空表格。

## 测试策略

- 后端：优化建议生成函数抽为可测单元——给定 (category, title, 模拟搜索结果) → 断言 suggestion 文案分支正确（年份符→给名；年份不符→提示核对；剧集季→回退提示）。搜索用注入的假实现，不触网。
- 现有 fetch_posters 分组/回填测试保持通过（FailedItem 加字段后补构造）。
- 真机：点「更新海报」→ 进度更新 → 表格出现，排序/去首级目录/单行/建议名正确；未命中项库未被改。

## 明确不做（YAGNI）

- 不自动改库（用户手动改）。
- 不在表格内做「一键改名」操作列（本次只展示建议；如需可后续迭代）。
- 优化建议不接非 TMDB 数据源。
- 建议名不做模糊打分，仅年份校验（避免系列内误配）。

## 风险

- 优化建议探测使未命中条目额外发请求，略增耗时——仅对未命中项（通常几十条），可接受。
- 建议名仍可能对同年多部系列片（如龙珠剧场版）误配——年份校验能挡住跨年误配，同年多部仍可能不准，故文案措辞为「建议」而非「确定」，且用户手动确认后才改。
- 建议列超长文案省略显示，靠悬停看全文（已与用户确认此方案）。
