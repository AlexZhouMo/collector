# 漫画打开加速 + 翻页动画放慢 · 设计

日期：2026-09-15
分支：`feat/ui-home-icons-fullscreen-layout`（本次改动为该分支上的独立特性）

## 背景与目标

漫画阅读器存在两个体验问题：

1. **打开一卷略慢**：打开卷时后端需要拿到每页宽高（用于判断横向对开页），当前实现为此把整卷每页字节完整解压一遍，几百 MB 的卷会有数秒到数十秒开销。
2. **翻页动画偏快**：当前翻页 3D 卷动动画时长 0.72s，卷动过程一闪而过，缺少「翻动书页」的重量感。

目标：打开显著加速（首屏秒级可读），翻页动画放慢到有清晰的卷动感。

## 涉及文件

- `src-tauri/src/comic/reader.rs` — 页尺寸读取（加速 A 核心）
- `src-tauri/src/comic/mod.rs` — `comic_pages` 命令、后台补正事件（加速 B）
- `src/views/ComicReaderView.ts` — 打开流程两阶段化（B）、zip 缓存/预取（C）
- `src/lib/spreads.ts` — 对开分组（B 的重排逻辑复用）
- `src/lib/ipc.ts` — 若新增命令/事件类型
- `src/styles/theme.css` — 翻页动画时长（放慢）

## 加速方案 A · 只读图片头部尺寸，不全解压

**问题根因**：`reader.rs::list_pages_with_dims` 对每个 zip 条目 `read_to_end` 读出完整字节，再交给 `image::ImageReader` 解析尺寸。整卷字节全进内存，是主要耗时来源。

**改法**：改为流式只读头部。对每个条目：

- 用 `ZipArchive::by_name` 拿到条目 reader（`ZipFile` 实现 `Read`）。
- 不再 `read_to_end`。改为逐步读入一个小缓冲（如先读 64KB），用 `image::ImageReader::with_guessed_format().into_dimensions()` 尝试解析尺寸；JPEG/PNG 的尺寸信息都在文件头部，几十 KB 内可得。
- 若头部不足以解析（极少数大头部/渐进式），退回读更多字节直到成功或读完；解析仍失败按 (0,0) 处理（前端按竖单页默认），沿用现有降级语义。

**验收**：`list_pages_with_dims` 不再把整页字节读入内存；对一卷数百 MB 的 zip，耗时从「全解压」量级降到「读头部」量级。现有三个测试（正常尺寸、损坏图降级、排序）保持通过，尺寸解析行为不变。

## 加速方案 B · 首页秒开，尺寸后台补正

**目标**：打开卷时立即渲染第一页，让用户马上能读；每页宽高在后台算完后再校正对开分组。

**流程**（`ComicReaderView`）：

1. **阶段一（立即）**：打开卷先调用一个「只列页名、不含尺寸」的快速路径（复用 `reader::list_pages`，本就只读中央目录、毫秒级），把所有页当作**竖单页**先构造 spreads 并渲染首页（封面）。此时用户已可阅读、可向后翻。
2. **阶段二（后台）**：后端在 `spawn_blocking` 里跑方案 A 的头部尺寸读取，完成后通过一次性事件（如 `comic-dims`，携带 `zip_path` + `PageInfo[]`）把带尺寸的页表发回前端。
3. **前端收到尺寸后**用 `buildSpreads` 重算对开分组，并**就地校正**：仅当当前所在页的分组发生变化时才平滑更新视图，否则只更新内部 spreads 数据，避免「跳一下」。

**避免观感跳动的约束**：

- 阶段一按竖单页分组，与阶段二结果在「竖图为主的卷」上高度一致，绝大多数卷不会有可见重排。
- 校正时若用户正在翻页动画中（`flipping`），推迟到动画结束再应用。
- 若用户已翻到的页在重排后索引变化，按「当前显示的页名」重新定位 `idx`，保证看到的页不跳。

**验收**：打开卷后首页在感知上「立即」出现（不等全卷尺寸）；尺寸补正后横向对开页正确合并；补正过程无明显闪烁或页码跳动。

## 加速方案 C · zip 缓存与下一对开预取

**问题**：`comic_page` / `read_entry` 每次都 `File::open` + `ZipArchive::new`（重建中央目录），翻页时每页重开一次 zip。

**改法**（两点，均为前端可感知的翻页顺滑度提升）：

1. **前端预取**：`ComicReaderView` 已有 `cache: Map<name,url>`。在 `render` 完成后，**预取下一对开**（`spreads[idx+1]` 的 left/right）图片 URL 存入 cache，使点「下一页」时图片已就绪，翻页动画期间不等 IO。可选同时预取上一对开。
2. **后端 zip 句柄复用（可选增强）**：如仍有可感知延迟，再引入按 `zip_path` 缓存打开的 `ZipArchive`（Tauri State 中的 `Mutex<LruCache>`），避免每页重开。**默认先只做前端预取**；若预取已让翻页跟手，则 C 的后端部分按 YAGNI 不做，留作后续。

**验收**：连续翻页时，下一页图片在多数情况下已缓存，翻页动画启动即有内容，无「点了等一下才翻」的延迟。

## 翻页动画 · 放慢到 1.3s

**现状**：`theme.css` 中 flipper 的 `transition` 与 shade/glare 动画均为 0.72s，缓动 `cubic-bezier(.36,.05,.2,1)`。

**改法**：

- `.book .flipper` 的 `transition` 时长 0.72s → **1.3s**，缓动曲线不变（保留重量感）。
- `.flipper.flip-next .shade` 与 `.flipper.flip-next .glare` 动画时长同步 0.72s → **1.3s**。
- `ComicReaderView.go()` 的兜底 `setTimeout(…, 900)` → 需大于动画时长，改为 **1500ms**（略大于 1.3s），确保 `transitionend` 未触发时也能正确收尾。

**验收**：翻页卷动过程明显放慢、可清晰看到书页转动；快捷键/按钮连续翻页时 `flipping` 锁在动画期间正常阻止叠加，收尾无残留 flipper。

## 测试策略

- **后端**：`reader.rs` 现有单测保持通过（尺寸正确、损坏降级、排序）；新增/调整测试验证只读头部路径对正常 JPEG/PNG 返回正确尺寸，且不依赖整页读入。
- **前端**：无单测框架，靠手动验证——打开大卷观察首屏速度、尺寸补正后对开正确、翻页预取顺滑、动画时长与收尾。
- **回归**：缩放/平移、封面单页居中、横向对开合并、末页落单等既有行为不变。

## 非目标（YAGNI）

- 不改漫画封面缩略图流程（`comic_volume_cover`）。
- 不引入图片二进制传输替换 base64 data URL（本次不做，若首屏仍慢再议）。
- C 的后端 zip 句柄缓存默认不做，仅在前端预取不足时再启用。
