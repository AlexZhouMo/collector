# 文件夹与单条目移动（影视/漫画/游戏，同类型内自由移动）

日期：2026-09-18

## Context（为什么做这件事）

影视/漫画/游戏三类型目前的"移动"能力不完整：
- 单条目移动：Video/Game 有（`MoveDialog` + `supportsMove:true`），但树只含当前分类；Comic 完全没有（`supportsMove:false`）。
- 文件夹移动：**完全没有**——文件夹只能改名（`rename_folder`），不能挪位置。

需求：三类型都支持"移动"（文件夹 + 单条目），**同类型内自由移动**（如影视的电影↔动漫↔剧集），**三类型间不可互移**（影视不能进漫画/游戏）。

## 已确认的关键决策

- **粒度**：文件夹移动 + 单条目移动都做。
- **跨类型隔离**：移动对话框只显示同类型的目录树，从源头杜绝跨类型（选不到，而非选后报错）；后端命令再兜底校验。
- **磁盘处理**：移动**只改数据库分类/路径 + 字幕跟随，视频文件本身不动**（与漫画/游戏的 DB-only 一致）。用户明确表示不处理视频跨顶级分类后的磁盘路径一致性问题（其使用场景不触发）。
- **UI**：复用现有 `MoveDialog`（树+搜索+展开折叠），影视场景把电影/动漫/剧集三分类合成一棵树；分类顶层节点**不加图标**，纯文字 + "（分类）"标注。

## 移动规则（按类型）

- **影视内部**：文件夹/单条目可在 电影↔动漫↔剧集 及各自子目录间自由移动。移动 = 改 `category`（顶级分类）+ `category_path`（子路径）+ 字幕跟随。视频文件不动。
- **漫画内部**：在"漫画"分类目录树内移动，改 `category_path`（DB-only）。
- **游戏内部**：在"游戏"分类目录树内移动，改 `category_path`（DB-only）。
- **禁止跨类型**：影视 ✗ 漫画/游戏，反之亦然。

## UI 设计

**移动对话框**（复用 `MoveDialog` 扩展）：
- 树结构：影视=电影/动漫/剧集三分类合成一棵（顶层三个"分类"节点，各展开为子目录树，可跨分类选目标）；漫画/游戏=各自单分类树。
- 分类顶层节点：纯文字名 + "（分类）"灰标，**无图标**。
- 当前位置/被移动项：灰显 + 标记（单条目"当前位置"、文件夹"移动中"）。
- 文件夹移动：**排除自身及子树**（不能移进自己或自己的子目录，灰掉禁选）。
- 搜索、展开折叠沿用现有交互。

**入口**：
- 单条目移动：三视图卡片右键菜单"移动"（Comic 补上）。
- 文件夹移动：FolderView 文件夹右键/操作菜单加"移动"。

## 后端设计

- **单条目移动**：复用 `media_update`（已支持改 category+category_path+字幕跟随）；漫画/游戏用 `comic_update`/`game_update`（需确认能改 category_path，不能则补）。
- **文件夹移动**：新增 `move_folder(kind, category, old_path, target_category, target_path)` 命令：
  - DB 级联更新该文件夹及所有子孙的 `category`（影视跨分类时）+ `category_path`（父前缀替换为目标路径 + 文件夹名）。复用 `rename_folder_in_db` 的级联 SQL 思路。
  - 字幕目录跟随：`subtitles/<category>/<old_path>` → `subtitles/<target_category>/<target_path>/<folder_name>`。
  - 校验：目标 kind 与源一致（前端已从树杜绝，后端兜底）；目标不能是自身子树；目标位置无同名冲突。
- **跨类型隔离**：`move_folder` 的 target_category 必须属于同一 kind（影视三分类同属 Video）。

## 现有可复用

- `MoveDialog`（`src/components/MoveDialog.ts`）：树渲染+搜索+展开，扩展即可。
- `matchTree`（`src/lib/moveTreeFilter.ts`）：树搜索过滤。
- `buildVideoTree`（`src/lib/videoTree.ts`）：建目录树——影视需扩展为"三分类合一"。
- `rename_folder_in_db`（`src-tauri/src/lib.rs`）：级联更新 category_path 的 SQL 模式，move_folder 参考。
- `media_update` 的字幕跟随逻辑（`src-tauri/src/lib.rs:106`）：文件夹字幕跟随参考。

## 验证方式

- 单条目：影视里把一部电影移到动漫分类 → 库分类变动漫、字幕跟随、列表刷新正确；漫画/游戏内部移动正常。
- 文件夹：移动含多个视频+子目录的文件夹到另一分类 → 整棵子树 category/category_path 级联正确、字幕目录跟随、无同名冲突时成功、移进自身子树被拒。
- 跨类型：移动对话框里选不到其他类型（影视树无漫画/游戏节点）。
- `cargo test`（新增 move_folder 级联/校验测试）、`cargo build`、`npx tsc --noEmit` 全过。

## 已知取舍

- 视频文件不随移动挪磁盘（只改库+字幕）。跨顶级分类移动后，若播放靠分类拼路径可能对不上——用户明确表示其场景不触发，不做特殊处理。
- 本设计聚焦库/字幕层面的移动，不含磁盘视频文件的物理移动。
